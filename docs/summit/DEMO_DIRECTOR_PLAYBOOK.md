## 1. 任务 1 · 3 分钟 canonical 分镜（唯一版）

**通用规则**
- 每个点击后 **停 1.5–2s** 再开口；开口前先确认画面已到预期（脉搏/卡片/字幕）。
- 讲解词按 **中文口语 5.5–6 字/秒** 设计，括号内为约字数；超时就删词，不加速。
- 任一步失败：**3 秒内切兜底**（见任务 3），不在台上找按钮。
- 计时器不可见；主讲人自己不看表，由计时员在第 2:40 举牌。

### 开演前预热清单（逐项打勾）

1. `pnpm build && pnpm start`（生产构建；dev 仅用于脚本采集；**不要现场 build**）；
2. 浏览器 **100% 全屏**，隐藏书签栏/任务栏，开勿扰；计时器不可见；
3. **先注入一次故障并点「终止故障演练，恢复稳态」**，确认终止链路可用；
4. 「端侧日志审计」页签点一次「抓取并审计日志流」，确认引擎状态/降级文案可显示；

## 4. 任务 4 · 路演（自动演练）的定位与话术

**定位**：兜底与加分项，**不是主路径**。主路径永远是任务 1 的手动链路；路演用于"主讲人嗓子哑了/现场网络不可控/必须缩短讲解"的时刻。

**入口（真实文案）**：顶栏 **「剧本路演」** → 菜单选 **「OOM 全链路自愈约 34 秒 · 4 阶段」**（另有 CNI、节点 CPU 两个剧本）。
**运行时画面**：字幕条 aria **「自动演练序列器」**，顶部小标 **「RUNBOOK · 自动演练」**，阶段徽标依次为：
`阶段 1/4 · 全景稳态巡航` → `阶段 2/4 · 故障注入与空间锁定` → `阶段 3/4 · RAG 混合检索与多卡诊断` → `阶段 4/4 · MCP 闭环自愈`。
**控制按钮（aria）**：重播上一套剧本路演 / 收起剧本路演字幕条 / 暂停（继续）剧本路演 / 停止剧本路演并复位集群。

**标准话术（照读）**：
> 「这是为评委准备的自动演练模式，它把整条链路按时间轴跑一遍，讲解者只需要讲。」

**失败态**：字幕位显示 **「DEMO-PREFLIGHT · 未通过」**，提示 **「预检未通过：请检查 dev 依赖后重新启动」**；预检 5 项= 3D 视口存在 / store 可用 / Copilot 抽屉挂载 / SSE 非 fallback / WebGL 上下文未丢失。失败时**不要重试路演**，切回手动链路。

## 5. 任务 5 · 追问 Top 10（每题 ≤40 秒）

> 回答结构统一：**结论 → 证据（文件路径+数字）→ 边界（不夸大）**。

1. **和真实 K8s 什么关系？**
   「演示默认跑确定性仿真引擎：故障语义按真实 K8s 建模，数值是合成值，不声称是真实集群实测。真实集群适配层在，但这次没接。证据：白皮书第七章数据边界；`syntheticEngine.ts` 注释明说无 Math.random。」
2. **RAG 效果怎么证明？**
   「49 条评测用例：两路 Recall@1 88.9%、三路 94.4%（+5.6pp），MRR 0.927→0.976；负例拒答 100.0%，误拒 0%。文件：`docs/rag-eval.md`，可用 `pnpm eval:rag` 重跑，两次结果一致。」
3. **三路召回真的上线了吗？**
   「引擎支持 MinerLM 384 维查询向量，Worker embed 协议和 `/api/chat` 入参都做了；但浏览器端到端未真机验证，生产未开三路时自动两路。评测用的是预计算查询向量，这点我们在 R45 文档里写明了。」
4. **60FPS 是真的吗？**
   「不是。本机只有 SwiftShader 软渲染，实测 FPS 中位 5（均值 4.75），我们不能拿它当卖点。可验证的是硬件无关指标：235 draw calls（中位，均值 236.35）、154 mesh、27 个 InstancedMesh 承载 1,017 实例。白皮书 8.5 明确写了『无 GPU 环境声称 60FPS 不诚实』。」
5. **MCP 是标准实现吗？**
   「是 JSON-RPC 2.0 over HTTP：`/api/mcp` 支持 initialize / tools/list / tools/call / ping，错误码符合规范；不是 stdio transport。工具三个，执行复用 `/api/mcp/execute`（legacy 标注）。文件：`src/app/api/mcp/route.ts`。」
6. **端侧模型真跑了吗？**
   「权重已随包（`public/models/Xenova/all-MiniLM-L6-v2`，Apache-2.0），但这台机器端侧推理走的是 builtin fallback，0.12ms 不是神经网络延迟；页面会写明当前引擎，我们不冒充。」
7. **隐私安全怎么保证？**
   「端侧脱敏：100 条批量均值 8.88ms，约 11,264 条/秒；原始凭证不出浏览器。高危动作必须人工确认，执行有回执与 sha256 摘要。边界：这不是等保认证，只是架构层面的数据最小化。」
8. **没 Key/断网怎么办？**
   「自动切本地确定性容灾引擎，继续给结构化诊断与卡片；实测这次回落 6.7 秒（含重试），不是 1 秒。这是离线优先设计，白皮书 4.x 有说明。」
9. **多模态是真的看图吗？**
   「有 Key 时把 3D 截图作为 image 数组送模型；无 Key 时端侧算像素特征（红区连通块/质心/颜色占比），引擎 B 会引用真实统计值。R46 实测能说出『3 个连通块、质心右前』。」
10. **为什么不用向量数据库/LangChain？**
    「12 篇手册规模下引入外部向量库是过度设计：BM25+TF-IDF+RRF 在本地毫秒级（引擎 P95≈2ms），零外部服务、离线可跑。代价是没有 ANN 规模扩展性，这点在 RAG 文档里如实写了。」
