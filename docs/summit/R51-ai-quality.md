# R51 · AI 质量评测（20 问 · RAG vs 裸模型）

> 本地网关接通后执行：`http://127.0.0.1:3425/v1`，模型 `apt-goto/deepseek-flash`。
> 20 条问句 × 2 次（RAG / `disableRag:true` 裸模型）= **40 次真实模型调用**，
> 全部 `engine=llm`，有效配对 **20/20**。完整逐题数据见 `docs/ai-quality.md` / `.json`。

---

## 1. 环境与开关

- `.env.local` 指向本地网关（key 任意），模型 `apt-goto/deepseek-flash`；
- `/api/chat` 新增 `disableRag?: boolean`（仅评测用）：只跳过知识库注入，
  引擎/Prompt 结构/工具集完全不变，保证"单一变量"对照；
- 评测脚本 `scripts/eval-ai-quality.mjs`：20 问覆盖 OOM / CrashLoop / CPU / 网络 /
  DNS / 镜像 / Pending / etcd / APIServer / VXLAN / 巡检 / 容量 / 能力 / 流程等场景，
  故障题使用含真实 Pod/节点的上下文，动作题额外校验动作卡白名单与目标实体。

## 2. 汇总结果

| 指标 | RAG | 裸模型 | 差值 |
|---|---|---|---|
| 关键词正确率 | **91.7%** | 91.7% | 0.0pp |
| 引用命中率（RUNBOOK 引用/正文 id） | **95.0%** | 50.0% | **+45.0pp** |
| 动作合理性（期望动作题） | 100% | 100% | 0 |
| 平均 TTFT | **8,033ms** | 9,534ms | −1,502ms |
| 平均总时长 | **21,307ms** | 22,808ms | −1,502ms |
| 平均 prompt / completion tokens | 9,180 / 3,250 | 7,242 / 3,415 | +1,938 / −165 |

## 3. 解读（不美化）

1. **RAG 没有提升"关键词覆盖"**（91.7% vs 91.7%）：示例问句都是常见 K8s 故障，
   裸模型本身就能说出正确术语——正确率指标对两者不敏感。
2. **RAG 的价值体现在出处**：引用命中率 95% vs 50%（+45pp），
   根因卡/正文能给出 RUNBOOK 编号，裸模型一半情况下没有可核对出处。
3. **动作合理性两边都是 100%**：动作卡都由服务端构造器兜底并校验白名单与真实目标，
   与是否 RAG 无关（这是防御性构造的功劳，不是模型变聪明了）。
4. **RAG 反而更快**：TTFT/总时长低约 1.5s。可能是检索命中的手册片段让模型更快收敛，
   但单次评测噪声大，**不能据此断言 RAG 普遍更快**。
5. **成本更高**：RAG 平均 prompt tokens 多约 1,938（知识片段注入），
   与"质量换成本"的预期一致。

## 5. 未验证项与风险

1. **正确率是关键词命中率**，不是人工评分；不能证明推理链正确。
2. **单轮运行**：未做多次重复取均值，1.5s 的时延差在噪声范围内。
3. **引用命中率把"正文出现 RUNBOOK id"也算命中**，未逐条核对该 id 是否真的来自检索，
   裸模型也可能复述 Prompt 里的编号（本文按实测口径记录，不额外解释为"更懂"）。
4. **测试上下文是构造的**（故障 Pod/节点为固定样本），不是真实集群时序。
5. 网关是本地服务，模型真实能力/配额以网关为准；换模型后数字需重跑。
