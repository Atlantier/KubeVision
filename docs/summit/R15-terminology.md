# 术语表与语言一致性（R15 · 追问 3）

> 适用范围：TopBar / Copilot 抽屉 / Modal / Toast / 终端日志 / 路演旁白等**用户可见文案**。
> 代码标识符（类型、变量、事件名）不在此约束内，避免无谓重构。

---

## 1. 统一术语表

| 概念 | 唯一用词 | 禁用/替换项 | 说明 |
|---|---|---|---|
| 服务/组件出现异常 | **故障** | 异常、错误事件（用户文案） | 物：故障是"系统状态"，不是"人的错误" |
| 需要人注意的信号 | **告警** | 警报、警告（用户文案中统一为告警） | 告警有级别；"警告"仅用于 CSS/Tailwind 色阶语义 |
| 系统自动恢复动作 | **自愈** | 修复、调谐、自救、自动恢复（用户文案） | 强调"系统自身完成" |
| 人为消除故障 | **处置** | 修复 | 与自愈区分责任主体 |
| 自动演练 | **路演 / 自动演练** | 演示、Demo（中文文案） | 顶栏用"路演"，序列器标题用"自动演练" |
| 演练阶段 | **阶段** + 两位序号 | 步骤、Step（中文文案） | 如"阶段 02 故障注入" |
| 诊断结论 | **根因** | 原因（结论性文案） | "原因"仅用于描述触发条件 |
| 容器实例 | **Pod / 容器实例**（首次出现） | 实例（单独使用） | 与 K8s 术语一致 |

## 2. 句式规范

- 旁白：「动作 · 对象 · 结果」，例：`注入 Cgroup 内存溢出 · worker-beta · 捕获 3 个 OOMKilled`。
- 禁止感叹号、拟人语气（"我来帮你""让我们一起"）、Emoji。
- 事实数字必须来自 DemoFacts（真实快照），不得编造。

## 3. 本轮机械替换统计

| 替换 | 文件数 |
|---|---|
| `修复` → `自愈` | 35 个文件 |
| `调谐` → `自愈` | 同上（并入） |
| `异常` → `故障` | **未执行**（`异常` 在代码中亦指"异常检测/异常比例"等技术语义，仓促全量替换会改变可解释性与文案准确性；仅约定用户可见句式中使用"故障"） |

> 说明：`修复`/`调谐` 已全仓替换（含注释与用户文案）；`异常` 保留为技术术语，
> 用户可见句式由后续新增文案遵守"故障"即可。此决策避免"一律替换"造成的语义扭曲。

## 4. 未覆盖范围

- `src/utils/demoDirector.ts` 的旁白只做了去感叹号/去拟人机械清理，未逐句按术语表重写。
- Toast/Modal 的部分动态拼接文案（来自 API/日志）未做术语归一。
- 未新增 lint 规则强制术语（建议后续把禁用词加入 `check-a11y` 或独立 `check-terminology`）。
