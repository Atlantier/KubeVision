# Blender 硬件模型导出规范（KubeVision Hybrid GLTF Pipeline）

> 把符合本规范的 `.glb` 文件放进 `public/models/`，系统会在下次加载时**自动探测并替换**对应的程序化几何体。
> 未放置文件时，系统以高精度程序化几何体运行，**不会报错、不会阻塞首屏**。

---

## 一、文件命名与落点

| 文件名 | 挂载位置 | 替换的部件 | 未放置时的回退 |
|---|---|---|---|
| `worker-rack.glb` | `public/models/worker-rack.glb` | 三座 Worker 机架的**静态外壳骨架** | Round 6 程序化 `RoundedBox` 重工机柜 |
| `master-core.glb` | `public/models/master-core.glb` | 中心控制平面晶体核心 | 程序化八面体能量核心 + 旋转晶格罩 |

**探测机制**：客户端挂载后用 `HEAD` 请求探测文件，并校验 `Content-Type` 不是 `text/html`（避免把 Next.js 的 404 页面误判为模型）。探测失败时静默回退，**不产生控制台报错**。

---

## 二、包围盒尺寸基准

### worker-rack.glb（服务器机柜）

| 维度 | 推荐值 | 允许范围 | 说明 |
|---|---|---|---|
| 宽度（X） | **2.2 m** | 2.0 – 2.6 | 与程序化机柜 `RACK_BODY_SIZE[0] = 2.6` 对齐；略窄会在轨道上显得细 |
| 高度（Y） | **4.4 m** | 4.2 – 4.6 | 必须容纳 4 层托盘；低于 4.2 会顶穿顶层 Pod |
| 深度（Z） | **1.6 m** | 1.4 – 1.8 | 与 `RACK_BODY_SIZE[2] = 1.8` 对齐 |
| 原点 | **[0, 0, 0]** | — | **底座地面中心**：模型最低点必须落在 Y=0，X/Z 居中 |
| 正面朝向 | **+Z** | — | 机柜"正面"（带门/铭牌那侧）朝向局部 +Z |

> **原点为何必须在地面中心**：机架在场景中由 `getRackTransform(rackIndex)` 解算位姿后平移到轨道上。若原点在模型中心（Y 轴偏移一半高度），模型会**陷进地面一半**。

### master-core.glb（控制平面核心）

| 维度 | 推荐值 | 说明 |
|---|---|---|
| 包围盒 | **3.0 × 4.6 × 3.0 m** | 与程序化核心 `OCTA_RADIUS` 视野一致 |
| 原点 | **[0, 0, 0]** | 晶体几何中心；该模型在场景中悬浮于 `y ≈ 2.9` |
| 正面朝向 | **+Z** | — |

## 三、内部结构基准（worker-rack.glb）

若模型包含托盘/隔板，请按下列 **Y 高度**对齐，Pod 方块会精确落在这些平面上：

| 层 | 托盘隔板 Y 高度 | 说明 |
|---|---|---|
| 第 1 层 | **0.0625** | 最低层 |
| 第 2 层 | **1.1125** | 层间距 1.05 |
| 第 3 层 | **2.1625** | — |
| 第 4 层 | **3.2125** | 最高层 |

每层 16 个插槽（4 层 × 2×2 列阵），Pod 可视盒高 0.56、落座偏移 −0.27。

**以下部件由系统保留，不需要建模**（即使建了也会被系统的动态件覆盖）：

| 保留部件 | 原因 |
|---|---|
| 12 条插槽底座环（SLOT_GHOSTS） | 单实例网格，跟随 Pod 布局实时变化 |
| 两根垂直霓虹导光柱 | `useFrame` 按节点状态色实时变色 |
| 腔体状态点光源 | 随健康度改变颜色与强度 |
| 4 层托盘隔板 | Pod 落座基准，层高必须与系统一致 |
| 底部 `<Html>` 铭牌 | 显示节点名 / 状态点 / CPU / MEM |
| 顶部光纤接口环 | `NetworkStream3D` 拱形光缆的落点 |

## 四、glTF 2.0 导出设置（Blender）

| 设置项 | 取值 | 原因 |
|---|---|---|
| 文件格式 | **glTF Binary (.glb)** | 单文件、内嵌贴图，避免多文件路径问题 |
| `+Y Up` | **勾选** | three.js 使用 Y 轴向上；不勾选会导致模型**躺倒** |
| `Apply Modifiers` | **勾选** | 否则倒角/阵列等修改器不生效，导出的是未修改的网格 |
| `Apply Transform` | **勾选** | 把物体变换烘焙进顶点，避免原点偏移 |
| 材质 | **PBR Metallic-Roughness** | three 的 `MeshStandardMaterial` 直接对应 |
| 贴图 | 内嵌（`Pack`） | 减少运行时 404 风险 |
| 动画 | **不导出** | 系统动画由 `useFrame` 驱动，模型动画会被忽略 |
| 三角面预算 | 单机架 ≤ **80,000 tris** | 三座机架同时渲染，需为 60FPS 留余量 |

### 材质建议（贴合深空赛博配色）

| 部位 | Base Color | Metallic | Roughness | 备注 |
|---|---|---|---|---|
| 机柜主体 | `#1e293b` | 0.45 | 0.32 | 与程序化机柜一致 |
| 金属棱边 | `#38bdf8` | 0.8 | 0.2 | 可另加自发光 |
| 散热格栅 | `#22d3ee` | 0.2 | 0.4 | 建议使用 Emission 自发光 |
| 深色凹槽 | `#0f172a` | 0.6 | 0.5 | — |

> **自发光**：Blender 的 `Emission` 会导出为 glTF `emissiveFactor`，three 自动识别。建议 `emissiveStrength ≤ 1.5`，过高会在后处理下过曝。

## 五、验证清单

放入模型后打开页面，逐项确认：

1. 控制台**无 404 / 无 glTF 解析报错**；
2. 机架**不悬空、不陷地**（原点与包围盒高度正确）；
3. 机架正面朝向相机方向（`+Z` 正确）；
4. 机柜有**投影**（系统已对所有子网格强制 `castShadow = receiveShadow = true`）；
5. 4 层 Pod 方块**精确落在**托盘平面上（层高基准正确）；
6. 拔掉机架电源（切换混沌场景）时，导光柱与腔体光源**仍能变色**（说明动态件未被覆盖）。

任一项不符时，删除 `.glb` 即可零成本回退到程序化几何体，系统不会因此损坏。
